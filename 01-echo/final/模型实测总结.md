# CR 模型实测总结（《回响》制作期间，2026-10-12）

**结论**：这次用过的模型里，图像最写实、角色最稳的是 **gemini-3-pro-image**，图生视频最可靠的是 **kling-v3-turbo-image-to-video**（24 条全部成功，人物不走样）。这两个结论只建立在这一部片子的用量上，样本小，下面写清楚哪些是测出来的、哪些只是一两次的观察。

所有数字来自本目录留下的任务记录（每个任务一份 `<name>.json`）。少数早期测试的记录被我删掉了，这些单独标出"记录已删、按会话日志计"。

**写实质感**（各一个样本，同一提示词，对比图 `work/ref-contact.jpg`）：gemini-3-pro-image 和 -preview 几乎一样，皮肤、毛呢质感和光线都像胶片剧照；nano-banana-beta 也写实，但人显得更老、更"摆拍"。

**角色一致性**（拿同一张定妆照编辑出"年轻 30 岁"，各一个样本，对比图 `work/young-contact.jpg`）：
- gemini-3-pro-image：脸型、眼睛、眉毛上的疤都保留了，像同一个人年轻了。选了它。
- nano-banana-beta：五官保留了，但没年轻多少。
- gpt-image-2：年轻了，但脸变得更多，像换了个人。

**用定妆照做参考图编辑 22 张关键帧**（gemini-3-pro-image）：中年版在各个角度都认得出是同一个人。年轻版大体一致，脸型略有浮动。22 张里有 4 张我判为不合格并重做：年轻版显老、笑容太假、镜子里没照出年轻的他、录音机上有品牌字样。这 4 张是内容不对，不是任务失败。

**耗时**：gemini-3-pro-image 19–124 秒，-preview 15–134 秒（约 20 条并发提交时）。

- kling-v3-turbo：22 个镜头人物都没走样，没有闪烁和变形，镜头运动偏保守。唯一没做到的是椅子自己弹回去那个镜头：动作没做出来，椅子没动。

## 三、参数和接口上踩过的坑

1. **minimax-h3 不收本地图片了。** skill 文档写的是"本地文件只有 minimax 接受"，实测 minimax-h3-image-to-video 收到 data URI 一律在提交时返回 HTTP 400 "Invalid video parameters for the selected model"，和图片大小、格式、带不带 duration 都无关：
   - 试过 800KB、127KB 的 JPEG、1280×720 的 PNG、640×360 的 JPEG；
   - 带 duration 和不带都试过。

   换成 HTTP URL 就成功。minimax-h3-reference-to-video 也一样被拒。request_id 示例：`01a1309d-a497-73a3-9345-a5cd4fef2391`、`01a130a0-1e83-7c32-b629-6ed9ae35d4ed`。
2. **`/unified/v1/assets` 用不了。** 这个接口文档里没写：GET 返回空列表，POST 要求 multipart 带 `model`。对试过的 6 个视频模型都返回 `invalid_asset`「Model has no portrait material primary route」，6 个是 seedance 2.0 fast 图生和参考图生、doubao-seedance-2-5-260628、minimax-h3 图生、wan2.7 图生、kling-v3-turbo 图生、happyhorse-1.1 图生。
3. **最后的绕法**：本地图交给 gemini-3-pro-image-preview 做"原样复刻"编辑。它返回的是上游对象存储的签名链接（腾讯云 COS，按签名约 12 小时有效），拿这个链接当视频首帧。复刻前后的对比我看过，画面几乎没变。缺点有两个：每张图多一次生成；链接过期后要重新复刻。
4. **seedance 对写实人脸很敏感。** 有真人脸的首帧、满座观众（剪影）的首帧、一段只描述雨声的文生视频，都返回 `content_policy_violation`。没有人脸的空镜可以用。
5. **gemini-3-pro-image 编辑时输出尺寸不固定。** 参考图是 16:9 的，有人物的编辑会出 1600×672（约 2.39:1），没有参考图、只传 16:9 时出 1376×768。
6. **kling-v3-turbo 图生视频的输出比例跟着首帧走。** 首帧 1584×672 → 输出 2208×936，正好适合宽银幕。
